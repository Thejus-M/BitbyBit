OpenClaw crossed 345,000 GitHub stars by giving any LLM a standardized way to use operating system tools. Install it, connect your model, pull a skill from ClawHub, and your agent can browse the web or read files without any custom code. That worked until February 2026, when Nous Research shipped Hermes Agent and reached 110,000 stars in 10 weeks.

The difference between them is one architectural decision: whether your agent's skills stay frozen at install day or compound over every run. This post covers what each framework actually does, where each one breaks down, and which architecture fits which problem.

What OpenClaw Actually Is

OpenClaw is an orchestration layer that sits between an LLM and the operating system. The LLM decides what to do; OpenClaw executes it by calling the appropriate skill. A skill is a sandboxed Python module paired with a manifest that declares its inputs, outputs, and required permissions. A web-browsing skill cannot write to the filesystem unless its manifest explicitly grants that permission.

ClawHub is the package registry for skills. Over 5,700 skills cover web search, file I/O, calendar access, database queries, and integrations for 19+ messaging platforms including WhatsApp, Telegram, Slack, Discord, Signal, and Teams. Docker deployment takes under 30 minutes from zero to running agent.

The LLM decides which skill to call. OpenClaw routes the request and returns the result. The skill boxes are static: they exist before the agent runs, they stay the same after.

The one thing OpenClaw does not do: sessions do not persist. Each conversation starts fresh with no memory of the previous run. The agent knows what each skill does; it does not know who it is talking to or what happened last Tuesday.

One serious limitation

Skills know what to do; the agent does not know who it is talking to. Each session begins from zero. A support agent that handled a user's billing issue last Tuesday has no memory of it on Wednesday. The skills are intact; the context is gone.

The Static Skills Problem

ClawHub skills are written once by a human contributor, published, and then frozen. When you install web-search@2.1.0, that is what you get until the maintainer releases 2.2.0. The skill has no mechanism to adapt to your specific LLM's output format, your team's naming conventions, or feedback from the agent's actual runs.

The more serious issue is supply chain risk. A security audit of ClawHub in early 2026 found approximately 12% of skills contained malware or exfiltration payloads. The same problem npm and PyPI face at scale. The difference: skills run with whatever permissions you granted them. A malicious skill does not need to compromise your system from the outside. You already invited it in.

Any skill in the dependency chain can carry a payload. The agent calls the skill; the skill runs with the permissions you granted. The malware audit finding was not theoretical.

Niche skills degrade fast. ClawHub has a well-maintained web-browsing skill and a reasonable gmail-send skill. It has nothing that knows your company's support ticket format, your internal API naming conventions, or the edge cases your specific LLM tends to produce. You write that yourself, it stays local, and it never improves.

The npm problem, now with AI agents

ClawHub skills run with the permissions you grant them. A malicious skill does not need to hack your system. You already gave it the keys. The 12% malware rate discovered in 2026 audits mirrors exactly what happened to npm packages in 2021 through 2023. The ecosystem grew faster than the vetting process could keep up.

Hermes Agent: Skills That Write Themselves

Nous Research released Hermes Agent in February 2026. The core architectural difference is one thing: when Hermes encounters a task it has no existing skill for, the LLM synthesizes one, tests it in a sandbox, and if it passes, writes it to the agent's local skill store. The next time a similar task appears, the agent retrieves the stored skill rather than synthesizing from scratch.

After 20 or more interactions in a domain, task completion speed increases approximately 40%. The agent has built a skill library tuned to the exact context of your deployment: your LLM's output format, your naming conventions, your edge cases. Persistent user profiles track each user's preferences, history, and communication style across sessions. The agent on Wednesday knows what happened on Tuesday.

The network grows with use. Each new node is a skill the agent generated and verified for this specific deployment. No external maintainer. No supply chain. The skill library reflects exactly the problems this agent has actually solved.

Multi-agent orchestration is native to the architecture. A coordinator agent can spawn sub-agents, delegate tasks, and receive results. Each sub-agent contributes to a shared skill pool. The more agents run, the faster the shared library converges on patterns that work.

What "self-learning" actually means mechanically

Hermes does not retrain the base LLM. Model weights stay frozen. What changes is the skill library indexed alongside the agent: a growing set of verified, deployment-specific functions that replace the need to re-synthesize. It is retrieval-augmented agency, not fine-tuning. The distinction matters for both compute cost and predictability.

Switching from OpenClaw to Hermes

The setup overhead is real. Hermes takes 2 to 4 hours to configure versus under 30 minutes for OpenClaw. The configuration covers model endpoint, persistent storage backend for skills and user profiles, sandbox policy for generated code, and orchestration topology if using multi-agent. None of that is difficult, but it is not a Docker run command either.

For projects already running on OpenClaw, the migration is not a direct port. OpenClaw skills are Python modules with a specific manifest format. Hermes does not import them. The practical path is to describe your existing skills in natural language and let Hermes regenerate them during the warm-up period. Budget 20 to 30 sessions before the agent's self-generated library matches the coverage you had from ClawHub.

The break-even point is roughly 20 sessions in a domain. Below that threshold, OpenClaw's pre-built skill library delivers faster value. Beyond it, Hermes's self-generated library compounds. For an agent handling a hundred sessions a week, the choice is clear. For a demo that runs twice, OpenClaw is better.

Stick with OpenClaw when:

  • You need immediate integration coverage: 19+ messaging platforms and 5,700 skills available the day you install.
  • Your deployment is short-lived: prototype, demo, or a one-time automation task that runs under 20 sessions.
  • You have no persistent storage backend: Hermes requires a place to store the skill library and user profiles between sessions.
  • Time to first run is constrained: the 2 to 4 hour Hermes setup investment is not always available.

Move to Hermes when:

  • The agent runs hundreds or thousands of sessions: the skill library compounds with every run, and the 40% speed gain applies to the long tail.
  • Persistent user context changes quality: a support agent that remembers preferences, a scheduling agent that learns patterns.
  • Security is a hard constraint: you cannot vet 5,700 external skill authors, and a 12% malware rate in the marketplace is not acceptable for your environment.
  • You are building domain-specific automation: skills tuned to your exact deployment outperform generic marketplace skills the more specialized the task.

Bottom Line

OpenClaw solves the cold-start problem: any LLM, 5,700 skills, running in under 30 minutes with connections to 19 messaging platforms. It is the right tool for prototypes and broad integration coverage where speed to deployment matters more than adaptation over time.

Hermes Agent is designed for the opposite problem: agents that run long enough for a learned skill library to matter, where persistent user context changes the quality of every response, and where you cannot afford a supply chain you do not control. The 2 to 4 hour setup is the price of that control.

  • Use OpenClaw for quick prototypes, demos, and multi-platform messaging integrations where 30-minute setup is a real constraint.
  • Use Hermes for production deployments where the agent runs enough sessions for skill accumulation and persistent user context to pay off.
  • If supply chain security is a hard constraint, Hermes's self-generated skill model removes the ClawHub dependency entirely. No external maintainer, no registry, no audit required.
